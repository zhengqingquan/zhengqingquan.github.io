利用Hexo等框架发布自己的文章时，文章发布后的顺序默认是按照创建时间排的。

但当一篇文章更新时其顺序依旧按照创建时间，这一点不太符合一般常识,这里我们要使发布后的文章在博客显示顺序按照更新时间.

文章按照时间排序通常分为按照文章的创建时间排序，或者按照文章的更新时间排序。

---

如果是将博客挂在github的流上时。每次提交都会更新文章的创建时间，导致所有文章的时间都是一样的，也就是你提交代码的时间。这明显是错误的。因此需要修改

可以参考Hexo中对[日期 / 时间格式](https://hexo.io/zh-cn/docs/configuration#%E6%97%A5%E6%9C%9F-%E6%97%B6%E9%97%B4%E6%A0%BC%E5%BC%8F)的设置

`updated_option` 的意思是，当 `Front Matter` 中没有指定 `updated` 时， `updated` 的值取什么。

那`Front Matter`是什么？

以下就是一个 `Font-matter`，说白了就是设置文章的一些信息，这些信息可以从 `post` 对象中获取：

```
---
title: 文章标题
author: 张三
categories: Blog Summary
tags:
 - Blog
 - Hexo
 - Hexo-theme-Next
---
```

----

在根目录下的配置文件 `_config.yml` 中有 `updated_option` 这个参数：

```yml
## updated_option supports 'mtime', 'date', 'empty'
updated_option: 'mtime'
```

这个参数的意思是当文章的 `Font-matter` 配置中没有 `updated` 属性时，这个值应该取什么？这里提供了 `mtime` 和 `date` 以及 `empty` 三个值。

- mtime : 使用文件的最后修改时间。这是从 Hexo 3.0.0 开始的默认行为。
- 使用 date 作为 updated 的值。可被用于 Git 工作流之中，因为使用 Git 管理站点时，文件的最后修改日期常常会发生改变。
- 直接删除 updated。使用这一选项可能会导致大部分主题和插件无法正常工作。

更新时间与文章创建时间一致。 虽然这样起不到“更新时间”的作用，但是至少不会无缘无故的对未更新的文件进行更新。
